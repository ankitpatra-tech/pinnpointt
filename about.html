05 // TECHNICAL FAQ

Frequently asked questions.

Quick answers to common questions about PinnPointt's direct transfer architecture.

How large of a file can I send?

There are no artificial file size limits. Whether moving a 10 MB document, a 4 GB archive, or a 50 GB+ raw 4K video reel, PinnPointt streams data in continuous small chunks directly into the browser's Origin Private File System (OPFS), eliminating memory spikes and tab crashes.

Do my files ever go to a cloud server?

Never. Your files stream directly device-to-device across your local Wi-Fi or peer-to-peer WebRTC DataChannels. No intermediate cloud servers ever receive, inspect, or store your payload bytes. Once the transfer completes, zero residual footprint remains.

Does it work between iPhone and Windows or Android and Mac?

Yes. PinnPointt is 100% web-standard based and works seamlessly across iOS Safari, Android Chrome, Windows Edge/Chrome, macOS Safari/Chrome, and Linux. No proprietary vendor ecosystem lock-in, external apps, or Bluetooth pairing required.

What happens if my Wi-Fi drops mid-transfer?

If the connection temporarily drops or either peer pauses, PinnPointt tracks byte offsets at the chunk level. As soon as the WebRTC DataChannel reconnects, the transfer resumes instantly from the exact paused offset without restarting from 0%.

How does PinnPointt verify my files aren't corrupted or malicious?

Every file undergoes hardware-accelerated SHA-256 integrity verification before transmission and after disk assembly. In addition, client-side safety heuristics triage incoming binaries, warning against deceptive double-extension traps and executable scripts before you save them.

DEEP DIVE // SPECIFICATION

Curious how it works under the hood? Read the technical summary

4-Channel Parallel WebRTC SCTP Pool

Transfers are multiplexed across four concurrent SCTP DataChannels with round-robin chunk dispatching based on low-watermark buffer backpressure to saturate local Wi-Fi speeds.

Direct-to-Disk Stream Handling

Chunks stream directly into Origin Private File System handles using FileSystemWritableFileStream, eliminating browser tab RAM spikes and crash risks on multi-gigabyte transfers.

WebRTC Transport Encryption

Direct peer connections are cryptographically authenticated and encrypted using DTLS 1.3 with AES-GCM-256 ciphers. Zero unencrypted packets ever traverse the network.

Hybrid Serverless Signaling Relay

When WebSocket signaling is blocked, peers can bootstrap SDP offers and ICE candidates through decentralized, ephemeral Nostr relays (NIP-01) with zero server persistence.
